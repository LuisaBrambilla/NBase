Gen360 — Project Summary

Gestão do Estoque Normativo 360 — A web application for querying and managing regulatory acts (atos normativos) from ANA (Agência Nacional de Águas e Saneamento Básico — Brazil's national water agency).

Key Features

  1. Public API — browse, search, and filter regulatory norms by year, number, subject, status, full-text, etc. (/public/atos, /public/filtros, /public/resumo).
  2. Admin Panel — protected dashboard where admins register, log in (with MFA), manage their profile, verify norms, and view statistics.
  3. Data Scraping & OCR — scripts to scrape the DOU/DODF (Brazilian official gazette) and OCR PDFs to populate the database.

Database Schema (PostgreSQL)

  • norma — main table for regulatory norms (number, year, publication date, subject, status, origin, full-text, etc.).
  • admins — admin users with email, hashed password, MFA secret, and active flag.

MFA Implementation — TOTP (Not a Google API)

This project does not use any external Google API for MFA. It implements the TOTP (Time-based One-Time Password) standard — the same open protocol used by Google Authenticator, Microsoft Authenticator, Authy, etc.

Core Functions in api/auth.py

FunctionPurpose
gerar_mfa_secret()Generates a random 20-byte Base32-encoded shared secret.
gerar_otpauth_uri(secret, email)Builds a standard otpauth://totp/… URI for QR code rendering.
_totp_code(secret, timestamp)Core TOTP algorithm (RFC 6238): HMAC-SHA1 + dynamic truncation → 6-digit code.
verificar_totp(secret, code, window=1)Validates user-supplied 6-digit code with ±1 time-step tolerance.

Registration Flow

User fills email + password ↓ POST /admin/register → server generates MFA secret + otpauth URI ↓ Frontend renders QR code (using qrious.js library) ↓ User scans QR in Google Authenticator / any TOTP app ↓ User enters 6-digit code from app ↓ POST /admin/register/confirm → server verifies TOTP code → creates admin

Login Flow

POST /admin/login { email, senha } ↓ If MFA enabled → returns { mfa_required: true } ↓ Frontend shows MFA code field ↓ POST /admin/login { email, senha, mfa_code } ↓ Server verifies password + TOTP → returns JWT token

Key Concepts

  • Shared secret — a Base32-encoded random key known to both server and authenticator app.
  • Time step — current Unix time ÷ 30 seconds = counter value.
  • HMAC-SHA1 — the counter is HMAC'd with the shared secret.
  • Dynamic truncation — extracts a 6-digit number from the HMAC digest.
  • Window tolerance — checking ±1 time step handles minor clock differences.

The implementation in api/auth.py (lines 88–122) is a complete, standalone TOTP implementation — no Google API calls are made. Any standard TOTP authenticator app (Google Authenticator, Authy, Microsoft Authenticator, 1Password, etc.) will work with it because they all follow the same RFC 6238 standard.
