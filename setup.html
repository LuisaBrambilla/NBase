Quick Start (Copy-Paste)

Open PowerShell in the Gen360 project root:

# 1) Start PostgreSQL in Docker
docker run -d --name gen360-postgres `
  -e POSTGRES_DB=normas `
  -e POSTGRES_USER=postgres `
  -e POSTGRES_PASSWORD=Newpr2026@ `
  -p 5432:5432 `
  postgres:16

# 2) Wait for readiness
Start-Sleep -Seconds 5
docker exec gen360-postgres pg_isready -U postgres

# 3) Apply database schema + migrations
Get-Content db\models.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas
Get-Content db\migracoes\002_origem_dodf.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas
Get-Content db\migracoes\003_admin_mfa.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas
Get-Content db\migracoes\004_verificacao_normas.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas

# 4) Install Python dependencies
pip install -r requirements.txt

# 5) Set environment variables
$env:DB_HOST="localhost"
$env:DB_PORT="5432"
$env:DB_NAME="normas"
$env:DB_USER="postgres"
$env:DB_PASSWORD="Newpr2026@"
$env:JWT_SECRET="local-dev-secret"
$env:CORS_ORIGINS="*"

# 6) Start API server (with hot-reload)
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload

# 7) In a NEW terminal — serve the frontend
python -m http.server 3000 --directory admin_frontend
✅ Done! API → http://localhost:8000 • Frontend → http://localhost:3000 • Swagger → http://localhost:8000/docs

# Then re-run the docker run command above

Persistent Data (optional)

To keep data across container removal, add a named volume:

docker run -d --name gen360-postgres `
  -e POSTGRES_DB=normas `
  -e POSTGRES_USER=postgres `
  -e POSTGRES_PASSWORD=Newpr2026@ `
  -p 5432:5432 `
  -v gen360-pgdata:/var/lib/postgresql/data `
  postgres:16

Deployment

Automated (recommended)

cd setup
.\deploy_azure.ps1 -PostgreSQLHost "20.226.39.175"

Manual — Deploy API

# Login
az login --tenant 6b1db0da-c53f-48bf-b271-9297590ad872
az account set --subscription "618a82e3-0571-4142-b50d-c8d2c34060ae"

# Create ZIP package
$tmp = "$env:TEMP\gen360_deploy"
New-Item -ItemType Directory -Path $tmp -Force
Copy-Item api, db -Destination $tmp -Recurse
Copy-Item requirements.txt, runtime.txt -Destination $tmp
Compress-Archive "$tmp\*" "$env:TEMP\gen360.zip" -Force

# Deploy
az webapp deployment source config-zip `
  --resource-group DemoGoverno `
  --name app-gen360-api `
  --src "$env:TEMP\gen360.zip"

# Clean up
Remove-Item $tmp -Recurse -Force
Remove-Item "$env:TEMP\gen360.zip" -Force

Manual — Deploy Frontend

$key = az storage account keys list --account-name stgen360frontend `
  --resource-group DemoGoverno --query "[0].value" -o tsv

az storage blob upload-batch `
  --account-name stgen360frontend `
  --account-key $key `
  --destination '$web' `
  --source admin_frontend `
  --overwrite

View Production Logs

az webapp log tail --name app-gen360-api --resource-group DemoGoverno

Local vs Production Comparison

🖥️ Local

  • PostgreSQL 16 in Docker
  • User: postgres
  • Uvicorn with --reload
  • Single process
  • CORS: *
  • JWT secret: any string
  • Frontend: python -m http.server

☁️ Production

  • PostgreSQL 14 on Ubuntu VM
  • User: linuxuser
  • Gunicorn + 4 Uvicorn workers
  • Azure App Service B1
  • CORS: specific origins only
  • JWT secret: 64-char random
  • Frontend: Azure Static Website

Docker Issues

🔴 "failed to connect to the docker API"

Cause: Docker Desktop engine is not running.
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
# Wait 10–15s, then:
docker info | Select-String "Server Version"

# If still failing, switch context:
docker context ls
docker context use desktop-linux   # or "default"

🔴 Port 5432 already in use

netstat -ano | findstr :5432

# Remove old container and recreate
docker rm -f gen360-postgres
# Re-run the docker run command

# Or use a different port
docker run -d --name gen360-postgres -p 5433:5432 ...
# Then set $env:DB_PORT="5433"

🔴 Container exists but stopped

docker ps -a --filter name=gen360-postgres
docker start gen360-postgres
docker exec gen360-postgres pg_isready -U postgres

Database Issues

🔴 "password authentication failed"

Cause: Password mismatch between env vars and container.
# Verify container accepts connections
docker exec gen360-postgres psql -U postgres -c "SELECT 1"

# If password changed, recreate container (destroys data):
docker rm -f gen360-postgres
docker volume prune -f
# Re-run docker run command

🔴 "relation 'norma' does not exist"

Cause: Schema not applied.
Get-Content db\models.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas
Get-Content db\migracoes\002_origem_dodf.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas
Get-Content db\migracoes\003_admin_mfa.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas
Get-Content db\migracoes\004_verificacao_normas.sql -Raw | docker exec -i gen360-postgres psql -U postgres -d normas

🔴 API starts but DB queries fail

# Check env vars are set
Write-Host "DB_HOST=$env:DB_HOST DB_PORT=$env:DB_PORT DB_NAME=$env:DB_NAME DB_USER=$env:DB_USER"

# Test connection directly
python -c "from db.db import get_connection; c=get_connection(); print('OK'); c.close()"

Python / API Issues

🔴 "ModuleNotFoundError: No module named 'fastapi'"

pip install -r requirements.txt

# If using a venv:
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

🔴 Uvicorn won't start / port 8000 in use

netstat -ano | findstr :8000
# Kill the PID shown, or use a different port:
python -m uvicorn api.main:app --port 8001 --reload

Frontend Issues

🔴 CORS errors in browser console

# Ensure CORS_ORIGINS is set
$env:CORS_ORIGINS="*"

# If serving frontend from a specific port:
$env:CORS_ORIGINS="http://localhost:3000,http://localhost:5500"

🔴 Frontend calls Azure prod API instead of localhost

Cause: The HTML page is missing <script src="./config.js">. Without it, JS files fall back to the hardcoded Azure URL.

Ensure every HTML page loads config.js before other JS files:

<script src="./config.js"></script>     <!-- FIRST -->
<script src="./theme.js"></script>
<script src="./admin_auth.js"></script>

🔴 "Erro ao conectar" / Network Error

  1. Confirm API is running: curl http://localhost:8000/health
  2. Check browser DevTools → Network tab
  3. Open DevTools Console — check API_BASE_URL value
  4. If using file:// protocol, switch to python -m http.server

🔴 "Tracking Prevention blocked access to storage" (QR code library)

Cause: Browser tracking protection blocking CDN. This only affects the QR code on the registration page. The registration itself still works — you just won't see the QR image. Use the otpauth_uri from the API response to manually add to your authenticator app.

Full Reset (Nuclear Option)

# Stop everything
docker rm -f gen360-postgres
docker volume prune -f

# Remove env vars
Remove-Item Env:DB_HOST, Env:DB_PORT, Env:DB_NAME, Env:DB_USER, Env:DB_PASSWORD, Env:JWT_SECRET, Env:CORS_ORIGINS -ErrorAction SilentlyContinue
